# CKai⇄DSH 接続規則（下書き v0.2、モコ作成 2026-11-11、CKai査読反映済み）

状態: 下書き v0.2。最終確定は根本さん。bridge実装（--uuid／--list／--workspace）は確定を待たずに進行可（モコ判断 2026-11-11）。

## 設計の芯（3つ）

1. あて先は名前ではなく UUID で固定する。タイトルは表示専用で、宛先の根拠にしない。
2. 既定は「新規タスク＝新規セッション」。継続は同じタスクのときだけ。失敗した文脈に別件を混ぜない。
3. 開く・指定する・引き継ぐ・閉じる、の各操作に台帳（対応表）を持ち、操作の前に台帳で確認する。

## 1. セッション台帳（対応表）

- 台帳は `knowledge/code_knowledge/dsh_sessions.json`（運用・機械可読）と `dsh.md`（説明）。
- 1セッション1行。項目：uuid／workspace／agent_preset／title（参考）／task（thread_id と task id の対応）／state（open|closed）／updated／handover_ref／last_failure。
- 台帳に無いセッションは原則として開かない。bridge も台帳外の指定を拒否する（発見手順は `--allow-unlisted`）。
- 同一性は「ワークスペース＋セッション＋agent preset」の3点。

## 2. あて先の同一性（ピン留め）

- セッションを開くときは UUID で指定する。名前の部分一致・先頭・引数なしの既定は宛先決定に使わない。
- UUID が取れない時は名前一致へフォールバックせず、止めて報告する。
- 「開けた」ことと「正しいセッションを開けた」ことは別の事実として扱う。送信前の確認を省略しない。

## 3. 新規／継続の既定

- 新規タスクは新規セッション。継続は台帳の open セッション。
- 失敗・停止した操作のあるセッションには、別件を送らない。再試行・後始末だけが許される続き。
- 迷ったら新規に切る（混入のコスト > 引き継ぎ要約のコスト）。

## 4. セッションの発見（例外手順）

- 台帳に無いセッションを開く必要が出たときだけ、一覧（UUID／タイトル／最終更新）を取得し、特定してから開く。特定したら台帳に登録してから使う。
- 「先頭」「最新」だけで宛先を決めない。

## 5. ワークスペース（プロジェクト）の指定

- DSHへの指示はワークスペースを常に明示する。既定は PhronisisDSH。
- 別ワークスペースを開くのは指示側が明示した場合だけ。追加済みのものに限る。
- ワークスペースとセッションと preset は組で台帳に記録する。

## 6. 引き継ぎ（新規作成時）

- 継続事項を新規セッションで始める場合、最初のメッセージに引き継ぎ要約1枚（目的／現在地／決まっていること／未決のこと／参照先）。
- 要約なしで「続き」を新規セッションに投げない。

## 7. relay 書式（CKai→DKai）

- 名乗り：Code側カイ（CKai）から
- 宛先：DKai／ワークスペース名／セッションUUID／agent preset
- 目的：1行
- 本文：指示本体
- 期待する返答：形式（OKのみ／結果と根拠／質問だけ 等）。返答は原文のまま受け取る
- 参照：thread_id やファイルパス

自由文で投げない。短い疎通確認でも定型に乗せる。

呼称: DSH 側は 2026-11-14 から「DKai」（根本さん決定、モコ経由）。過去の記録は旧表記のままでよい。

## 8. 失敗時の扱い

- 送信前にモーダル等の遮蔽を確認し、あれば閉じる（dismiss_modals）。
- 完了判定は状態表示でなく本文を読む。
- 失敗文言（失敗／停止／エラーコード、例 UNKNOWN_MODEL）を会話領域で検知し、台帳の last_failure にメモ。
- 再試行は原因を直してから最大1回。直せない／2回目も失敗したらモコへ手紙で報告。
- モデル未設定系は設定を直すのが先。

## 9. 閉じる／残す

- タスク完了後は台帳で closed。実体は削除しない。
- 再開する場合は open に戻し、理由を1行メモする。

## 10. この規則自体の扱い

- この規則は CKai⇄DSH の接続にだけ適用する。モコ⇄CKai の手紙回線の規則とは混ぜない。
- 規則に無い場面はその場の判断で進めてよいが、判断と理由を台帳か knowledge に1行残す。繰り返し出る場面は次の改訂で取り込む。
- 改訂は モコ下書き → CKai査読 → 根本さん確定。軽微な運用メモは CKai 側で随時可。
