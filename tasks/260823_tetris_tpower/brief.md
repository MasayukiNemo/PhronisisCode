# brief.md — T変換パワー拡張

## 課題

現行 `docs/tetris/index.html` に、ボムではなく「Tに変えられる権利」をパワーとして追加する。3ライン1点、4ライン2点でパワーがたまり、たまったら現ブロックをTに変換できる（ホールドとは別枠）。一番熱いたまり方（1個しかたまらないか複数貯められるか含め）を議論して決定し、テトリスの世界を壊さずにピンチを救える機構として実装する。

## 前提条件

- [x] ベースは `docs/tetris/index.html` 1278行+α（オートセーブ/カウントダウン/3列レイアウト済み）
- [x] T変換はホールドとは別枠の権利とし、既存のSRS/HOLD/DAS等を後退させない
- [x] 単一HTML / file:// / localStorage 制約は維持

## 成功基準

- [x] 必須1: パワー蓄積 — 3ライン同時消しで1点、4ライン同時消しで2点がパワーゲージに加算される。1-2ライン消しでは加算なし
- [x] 必須2: 熱いたまり方の決定 — 1ストックのみか複数ストックか、ゲージの上限・消費・溢れの扱いが議論を経て決定され、brief軌跡に記録されること
- [x] 必須3: T変換実行 — パワーが1点以上ある時に、専用キー（例: G または W）で現落下ブロックをTに変換できる。変換はパワーを1点消費し、色はTの色（#a855f7）、向きは変換前のrotを引き継ぐ。壁際ではSRS壁キックを適用して成功すれば変換、失敗すれば変換せずパワーも消費しない
- [x] 必須4: ゲージUI — SIDEにゲージ（例: 3マスまたはバー）が表示され、現在のポイントと満タン状態が視認できる。貯まった際は発光演出、変換時は消費演出があること
- [x] 必須5: セーブ/ロード対応 — パワー値（powerStock/powerGauge）も `phronisis_tetris_save_v1` に含めて保存・復元されること
- [x] 必須6: リグレッションなし — 既存のスコア/レベル/T-Spin/オートセーブ/カウントダウン等が引き続きPASSすること
- [x] 任意1: 貯め方の演出（3ライン時に +1、4ライン時に +2 のポップ）
- [ ] 任意2: 溢れ時のボーナス（ゲージ満タンで4ライン消しした際の溢れをスコアに還元）

## 制約

- 技術スタック: 単一HTML / IIFE / Canvas 2D / localStorage のみ
- 配置: `docs/tetris/index.html` を上書き。行数は1300-1400行を目安とする
- キー体系: 既存8キー+S/L/Aに加え、T変換はG（またはW）を追加。preventDefault不要、ホールドCとは別
- 品質: `scripts/code_health_check.py --no-color` 5/5 PASS 維持

## 判断の軌跡（実行中に記録）

| 論点 | 選んだ案 | 潰した案 | 理由 |
|------|---------|---------|------|
| 加算 | 3ライン1点、4ライン2点、1-2ライン0 | 1-2ラインでも加算 | 難易度比例で狙って貯める遊びを生む。本質的シンプルさ（Kai 75% + Yuna一致） |
| ストック上限 | 上限3・3マスゲージ（POWER_MAX=3） | 上限1（Daedalus出荷案）、上限2（Gaia C2案） | 貯蓄→選択→放出のドラマで起伏最大。溢れ消失の焦りで緩みを補完。1行で1/2へ切替可能な構造でDaedalus懸念も担保（Artemis/Metis推しを統合） |
| 溢れ | 消失（演出のみ、スコア還元なし） | 微還元（溢れを50点等に還元） | シンプルさと満タン時の意思決定圧を優先。還元は任意2として将来拡張に回す（Metis/Yuna合意） |
| 無限ループ断ち | 変換由来消去は加算スキップ（isPowerConversion）+ 壁キック失敗は無消費（SRS失敗でキャンセル） | 加算あり/失敗でも消費 | Hayato警告を制約化。永久機関とバグ消費を封じ込める（Daedalus警告を採用） |
| UI/キー | SIDEに3マスゲージ（発光/消費演出、+1/+2ポップ）、G/W両対応 | バー表示/Gのみ/Wのみ | 追従性で3マスが最も伝わる。キー両対応でAZERTY等の被りも緩和（Artemis見積でコスト増なし） |
