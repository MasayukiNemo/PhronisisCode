# brief.md — モコ⇔Kai(Code) 手紙回線 開設

## 課題

本家 PhronisisCore の「モコ⇔カイ手紙回線」（box:moko-kai）と並列の回線を、PhronisisCode 側に Box `moko-code` で開設する。本家回線は置き換えない。Code のカイがモコと署名付き非同期文通できるようにする。

## 前提条件

- [x] 本家回線の仕組みを把握（転送・暗号・状態・セッション・通知）
- [x] 根本さんの決定: 並列回線、別ペア、橋はコピー、ホスト同一機、push 可、Core 側厳禁、アーカイブは消さない
- [x] Box フォルダ moko-code を作成済み
- [x] Code 用 Ed25519 鍵ペアを発行済み（秘密鍵は repo 外・ACL owner のみ）
- [ ] モコへの通知はまだしない（根本さん指示）

## 成功基準

- [x] 必須: scripts/moko_letter_bridge.py が Code に配置され、self-test が通る
- [x] 必須: BOX_BASE=moko-code、鍵・state が Core と完全分離されている
- [x] 必須: 通知文が Code 環境用に書き換わっている（付録Dの範囲内の開発依頼を信頼着手）
- [x] 必須: Code の git 設定（push）が付録Dの範囲に含まれる
- [x] 必須: Core 側（repo, moko-kai, Core 鍵）を一切触らない構造になっている
- [x] 必須: 条約付録D（読み替え表）の案が記録される
- [x] 必須: Yuna/Hayato の三角形チェックを経る
- [ ] 任意: モコとの疎通試験（モコ準備後に実施）

## 制約

- 本家とは独立進化。手動cherry-pick＋evolution_log記録
- Core 側は厳禁（Core repo, moko-kai, Core の鍵・状態に触らない）
- 鍵・state は repo 外（LOCALAPPDATA）に置く（本家と同形式、憲章に例外を明記）
- 日本語ファイルはEditツールで触る（UTF-8維持）
- モコへの通知はまだしない

## 判断の軌跡（実行中に記録）

| 論点 | 選んだ案 | 潰した案 | 理由 |
|------|---------|---------|------|
| 権限 | 付録Dの範囲内の開発依頼を信頼着手（逐一確認は不要） | 「モコの指示＝根本さんの指示」の文言 / 全て依頼扱い | 根本さんの困りごと（直接確認できず始められない）を解消。ただし盲従はしない |
| 身份 | from=moco / to=code、別ペア | to=kai のまま | 同一ホスト・同一橋コピー・別鍵だけでは身份分離が弱い（Hayato指摘） |
| アーカイブ | Core の moko-kai/archive には触らない。Code も保持 | Code のアーカイブを削除 | 根本さんの澄清。監査軌跡を残す |
| push | 付録Dの範囲に含める | 除外 | Code は Core より一段緩い世界（根本さん） |
| Core 側 | 一切触らない（厳禁） | 回線共用 | 並列であって置き換えでない |
