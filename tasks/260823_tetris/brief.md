# brief.md — テトリス風ゲーム

## 課題

カーソルキーとスペースキーで操作する、テトリスに似た落下ブロックパズルゲームをブラウザで遊べる形で作成する。
PhronisisCode の実装サンプルとして、インストール不要・単一HTMLで起動できるプロダクト品質を目指す。

## 前提条件

- [x] ブラウザのみで動作（ビルド不要、依存インストール不要）
- [x] コア操作はカーソルキー（←→↓↑）とスペースキーのみ。メタ操作として R（リスタート）/ P（ポーズ）のみ例外的に許容
- [x] PhronisisCode リポジトリ内で完結（リポジトリ外へのファイル出力なし）

## 成功基準

- [ ] 必須1: 7種テトロミノ（I/O/T/S/Z/J/L）がランダムに落下し、10x20フィールドに積み上がる
- [ ] 必須2: カーソルキー操作 — ←→移動、↓ソフトドロップ、↑回転（時計回り）、スペースでハードドロップが機能する
- [ ] 必須3: 接地後に固定、横一列が埋まれば消去・上詰め、スコア加算（1/2/3/4列で100/300/500/800点）
- [ ] 必須4: ゲームオーバー判定（スポーン時に衝突で終了）とリスタート（Rキー）が機能する
- [ ] 必須5: スコア・レベル・消去ライン数・NEXT表示が画面に表示される
- [ ] 必須6: レベルに応じて落下速度が上がる（初期800ms、レベル毎-60ms、下限100ms、10ラインでレベル+1）
- [ ] 必須7: ブラウザで `docs/tetris/index.html` を file:// 直開きおよび http 配信の両方でプレイ可能（Chromium 120+ 想定の Chrome/Edge 最新で動作確認）
- [ ] 必須8: ゴースト表示（落下予測）が表示される
- [ ] 任意1: ポーズ（Pキー）

## 制約

- 技術スタック: HTML5 + CSS + Vanilla JavaScript（Canvas 2D）。フレームワーク・ビルドツール不使用。単一HTML（CSS/JS内包）を正とする
- 配置: `docs/tetris/index.html` 単一ファイル（file:// 直開きで CORS 問題なし）
- 操作体系: コア操作はカーソル+スペースに限定。R/Pはメタ操作として明示的に例外（前提条件と整合）
- 回転仕様: 時計回りのみ（逆回転なし）。壁キックは簡易2パターン（右1→左1の順で衝突回避を試行。失敗時は回転キャンセル）。フルSRSは過剰として不採用
- 品質: `scripts/code_health_check.py --no-color` が exit 0（Hayatoゲート観点2の必須）

## 判断の軌跡（実行中に記録）

| 論点 | 選んだ案 | 潰した案 | 理由 |
|------|---------|---------|------|
| レンダリング方式 | Canvas 2D | DOM/div方式 | 10x20の高速再描画・ゴースト/エフェクトが簡潔。DOMは要素数増で再描画コスト高 |
| ファイル構成 | 単一HTML（CSS/JS内包） | 分割HTML/CSS/JS | file:// 直開きでの CORS 回避と配布容易性を優先。分割は保守性高いが配布時のパス解決リスクを避け単一HTMLを正とした |
| 回転方式 | 時計回りのみ + 簡易壁キック（右1→左1） | 逆回転あり / 壁キックなし / フルSRS | 逆回転は操作体系肥大化のため捨てた。壁キックなしは壁際ストレス高、フルSRSは実装過剰。右→左の2試行で実用と簡潔の均衡 |
| スコア体系 | 100/300/500/800 + レベル毎-60ms（初期800ms/下限100ms/10ラインでLv+1） | 固定速度 | テトリスらしさと加速のゲーム性を両立。数値未定義だった落下速度を具体化してテスト可能にした |
| 追加要素 | ゴーストあり、ホールドなし | ホールドあり | ホールドは操作体系を増やすため「選ぶことは捨てること」で切った。ゴーストは低コストで操作補助効果が高いため採用 |
| メタ操作 | R/Pのみ例外許容 | 全てカーソル+スペースに封じ込め | リスタート/ポーズをカーソルに割り当てると誤操作・直観乖離。メタ操作として2キーのみ例外化し前提と制約の矛盾を解消 |
